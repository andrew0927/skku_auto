# ROS 2 기반 자율주행 차량 설계 및 구현
"ROS 2 기반 자율주행 차량 설계 및 구현" 교재에서 사용하는 프로그램 설치 파일 및 실습 파일을 제공하고 있습니다.

## 수동·자율주행 실행

`src/control/driving/driving.ino`는 사용자가 배선·가변저항 보정 및 수동주행을
검증한 스케치 그대로 사용합니다. ROS 조향 명령은 이 스케치의 범위인 **-7~+7**,
ROS 모터 속도는 아두이노 PWM 범위에 맞춰 **-255~255**로 제한하며
`s<조향>l<왼쪽속도>r<오른쪽속도>\n` 형식으로 전송합니다. 260처럼 범위를 넘는
명령도 실제 전송 전 255로 제한합니다.
실행 스크립트는 아두이노를 업로드하지 않습니다.

```bash
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install     # 처음 한 번, 코드 수정 후

./run_autonomous.sh                # 차선 주행
./run_traffic_light.sh             # 차선 주행 + 빨간불 정지

./run_autonomous.sh 200            # 시작 속도 200 (0~255, 생략하면 255)
./run_traffic_light.sh 180
```

신호등 버전은 빨간불을 보면 `red_approach_speed`(기본 150)로 감속해 차선을 계속
따라가다가, 횡단보도 박스의 아래쪽 끝이 화면의 `crosswalk_stop_y`(기본 440, 화면 높이 480)
선을 넘으면 정지합니다. 정지 후에는 초록불을 볼 때까지 기다리며, Space로 다시
시작해도 출발합니다. 빨간불이 초록불로 바뀌면 `crossing_time`(속도 150 기준 2.5초, 빠르면 그만큼 짧게) 동안은 신호등이
화면에서 사라지고 차선이 안 보여도 멈추지 않고 150 속도로 직진합니다. 그 사이 차선이
보이면 바로 차선 추종으로 돌아가고, 그 거리를 지나면 평소처럼 차선이 없을 때 정지합니다.
빨간불 정지 직전의 차선 조향을 ±1(`crossing_max_heading`)로 제한해 기억해 두고, 초록불 출발 후 횡단보도를 건너는 동안에는 추정 경로가
그 값에서 ±1단계(`crossing_max_change`)까지만 바꿀 수 있습니다(초록 불빛에 매트가 물들어 인식이 흔들리기 때문).
횡단보도가 가까이 보이는 동안에도 같은 직진을 합니다.
정지 중 빨간불이 `red_release_time`(기본 3초) 동안 보고되지 않으면 초록을 못 알아봐도
출발하며, 횡단보도 근처에서 빨간불이 다시 보이면 다시 멈춥니다(`red_release_time:=0`으로 끔).
정지 중에는 신호등 영역의 픽셀을 정차 0.7초 후의 기준 영상과 비교해, 램프 크기의 뭉친
영역이 확 밝아지면(빨간색 제외) 색을 못 읽어도 초록으로 판정합니다. 빨간 램프가 화면 밖이어도
됩니다. 영역의 절반 이상이 한꺼번에 바뀌면(카메라 흔들림·노출 급변) 기준을 다시 잡습니다. 정지 중에는 정지 직전 신호등 위치의 램프 픽셀(빨강/초록)을 직접 읽어 YOLO가 신호등을 놓쳐도
빨간불을 유지합니다. YOLO 점수 `light_min_score`(기본 0.5) 미만의 신호등 박스는
무시합니다. YOLO가 신호등을 놓치면 횡단보도 근처에서 빨간/노란 램프 덩어리를 직접 찾습니다(가운데가 하얗게 포화된 1000px 이상의 덩어리만: 주황 벤치·자판기 화면 제외, 화면 끝에 잘린 신호등도 인정). 판정이 바뀔 때마다 신호등 조각이 `~/traffic_light_samples/`에 저장되므로,
주행 후 이 사진으로 색 범위를 조정할 수 있습니다.
횡단보도 박스가 덮는 높이의 차선 검출은 무시하고, 나머지 높이에서 보이는 차선을 직선으로
연장해 경로를 만듭니다(`lane_roi` 창에서 횡단보도 영역이 회색으로 표시됨).
차 바로 앞 차선이 안 보이면(매트 주름, 급커브) 먼 쪽 차선을 직선으로 연장해 감속 주행합니다. `traffic_light` 창에 신호등·횡단보도 박스와 정지선이 표시됩니다.
더 일찍 멈추려면 값을 줄이고(`crosswalk_stop_y:=360`), 더 가까이 가서 멈추려면 늘립니다.

자율주행 중 키보드 창에서 `w`/`s`를 누르면 최고속도가 ±10씩 바뀝니다.
정지 후 다시 출발해도 바꾼 값이 유지됩니다.

차량 카메라(C920)는 자동으로 찾습니다. 찾지 못하면 실행하지 않으며,
`cam_num:=번호`로 직접 지정할 수 있습니다. 모델은 작업공간의 `best.pt`를
사용하며 CUDA 사용이 가능하면 GPU, 아니면 CPU를 선택합니다. `device:=cuda:0`
또는 `device:=cpu`로 명시할 수도 있습니다.

새 키보드 터미널의 메뉴에서 선택합니다.

| 입력 | 동작 |
| --- | --- |
| `1` + Enter | 수동주행 선택, 초기 속도 0 |
| `2` + Enter | 자율주행 선택, 정지 상태로 대기 |
| Space | 자율 모드에서 시작·일시정지, 수동 모드에서는 정지 |
| 실행 중 `1` / `2` | 정지한 뒤 수동 / 자율 대기 모드로 전환 |
| `w` / `s` | 수동 속도 +10 / -10 (기본 제한 ±255) |
| `a` / `d` | 수동 조향 -1 / +1 (제한 ±7) |
| `x` | 즉시 속도·조향 0, 자율주행 일시정지 |
| `q` / Ctrl+C | 정지 후 전체 실행 종료 |

모션 플래너는 `autonomous_control_signal`에 계산 결과를 발행합니다.
키보드 노드만 `topic_control_signal`로 차량 명령을 전달하므로,
자율 모드 선택만으로 차량이 출발하지 않습니다. **2 선택 후 Space**가 필요합니다.

## 차선 추종과 조정

카메라는 원본 컬러 BGR 640×480 영상을 기본 10Hz로 입력합니다. 회색 변환이나
밝기 보정은 적용하지 않습니다. `input_period:=0.2`로 입력을 5Hz로 낮출 수 있습니다.
모델의 `lane2`를 기본 목표로 사용하고, `lane1`과 `lane2`가 함께 보일 때 측정한
차선 간격이 최근 2초 이내라면 `lane1`으로 `lane2` 중심을 추정합니다.
차선 화면에는 두 클래스의 윤곽과 선택된 목표 지점을 함께 표시합니다.

조향은 경로 오차에 비례해 계산하고 평활화하며, 기본 오프셋은 0입니다.
`steering_gain:=0.1`로 반응을 줄일 수 있습니다. 유효한 lane2 경로로 주행을
시작하면 바로 기본 속도 **255**를 보냅니다. lane1으로 목표 차선을 추정 중일 때는
`estimated_speed`(기본 **200**)로 낮춥니다. 신호등 판단은 기본으로 꺼져 있습니다.

새 판단이 늦거나(경로 지연), 차선을 놓치거나, 검출 결과가 이상해서 멈춰야 하는 상황이 와도
자율주행 중이면 마지막으로 움직이던 조향·속도를 일정 거리만큼(속도 150에서 `hold_time` **0.5초**,
200에서 0.375초, 255에서 0.29초로 자동 조정)
그대로 유지합니다. 그 사이 새 판단이 들어오면 바로 이어서 주행하므로 끊기지 않고
연속으로 움직입니다. 그 사이 유효한 판단이 없으면 정지합니다.
속도는 실행할 때 숫자 하나로만 정합니다. 앞쪽 경로의 목표 조향이 클수록 미리 감속하고(최대 조향에서 150),
횡단보도가 보이면 150으로 줄여 정지선에 항상 같은 속도로 도착합니다.
속도를 올려도 신호등 접근·횡단보도 통과·차선 추정 구간은 150(`red_approach_speed`,
`estimated_speed`)으로 감속합니다(-1을 주면 실행 속도와 같게). 빨간불 정지,
일시정지, 출발 전에는 유지하지 않습니다. 두 차선 미검출 뒤 직접 인식으로
복귀하면 바로 255를 사용합니다. lane1 기반 추정 시에는 200으로 낮추고,
추정에서 직접 인식으로 돌아오면 `reacquire_hold`(기본 **0.5초**) 동안
200을 유지한 뒤 255로 돌아갑니다.

미검출 유지 시간이 끝나거나 경로 수신이 0.6초, 원본 영상 나이가 1초를 초과하면
정지 명령을 생성합니다. 키보드/제어 명령이 0.5초 이상 끊겨도 시리얼 노드가
정지를 전송합니다. 아두이노 스케치에는 통신 단절 타임아웃이 없으므로 USB 자체를
분리한 경우 ROS에서 정지 명령을 보낼 수 없습니다. 이 경우 모터 전원으로 정지합니다.

## 차량 없이 검증

아두이노와 키보드 노드를 비활성화해 저장된 트랙 사진으로 인식·경로만 실행합니다.

```bash
./run_autonomous.sh enable_serial:=false enable_teleop:=false \
  data_source:=image show_image:=false
```

테스트는 `/dev/pts` 가상 시리얼만 사용하고 실제 차량 USB를 열지 않습니다.

```bash
source install/local_setup.bash
ROS_DOMAIN_ID=92 ROS_LOG_DIR=/tmp/ros2_ws_tests \
  PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q tests
```

## 주행 기록과 차 없이 검증

```bash
./run_traffic_light.sh 150 record:=true      # 주행하며 영상·명령을 laps/lap_날짜시각/ 에 저장
python3 tools/export_frames.py laps/lap_...  # 프레임 추출(초당 2장) + 6장 묶음 시트 + labels.csv
# labels.csv 에 정답 작성: steering -7(왼쪽)~+7(오른쪽), go 1/0
python3 tools/compare_labels.py laps/lap_... # 주행 당시 코드 action vs 정답
./replay_lap.sh laps/lap_...                 # 수정한 코드로 같은 영상 재생 → 기록·정답과 비교
```

재생은 카메라·아두이노·키보드를 열지 않고 도메인 77에서 실행됩니다. 기록 1분당 약 0.6GB.

## 시작 차선과 장애물(차량) 회피

전체 기능과 코드 위치 정리: [docs/traffic_light_and_obstacle_recognition.md](docs/traffic_light_and_obstacle_recognition.md) (신호등 및 장애물 인식)

```bash
./run_traffic_light.sh 200 lane:=1                        # 1차선에서 출발 (생략하면 2차선)
./run_traffic_light.sh 200 lane:=2                        # 회피는 기본으로 켜짐
./run_traffic_light.sh 200 avoid_obstacles:=false         # 회피 끄기
./run_traffic_light.sh 200 vehicle_backend:=yolo          # 차량 인식을 COCO yolov8n으로
./run_traffic_light.sh 200 enable_lidar:=true             # 라이다(/dev/ttyUSB0)도 함께 사용
```

차량은 차선 모델(best.pt)과 별도로 HybridNets 모델이 인식합니다(`models/hybridnets_384x512/`,
공식 가중치 hybridnets.pth를 TorchScript로 변환한 파일). GPU가 있으면 GPU(프레임당 약 26ms),
없으면 CPU(약 150ms)에서 돌아갑니다. 변환은 `tools/export_hybridnets_torchscript.py`로 다시 만들 수 있습니다.
회피는 상태 기계로 동작합니다(lane1이 왼쪽 차선). 동작은 수동 시범 run_04(신호등 이후, PWM 140~150)에서 사람이 한 것과 같습니다.

| 상태 | 동작 |
| --- | --- |
| 내 차선 | best.pt seg에서 보닛 바로 위가 lane1/lane2 중 어느 마스크인지(최근 1초 다수결, `/lane_under_car`). 안 보이면 출발 차선 + 차선 변경 기록. 둘이 1초 이상 다르면 seg에 맞춥니다 |
| 시작 | 내 차선의 앞차 박스 아래쪽이 y=310(`avoid_start_y`, 사람: 305~322)에 닿으면. 횡단보도가 보이거나 빨간불을 본 직후에는 시작하지 않음. 감속 없음 |
| 나가기 | 반대 차선 쪽으로 최대 조향 ±7(`avoid_steer`)까지 0.15초에 1단계씩. 방향 변화량(∫조향 dt)이 15에 도달할 때까지(seg가 옛 차선을 분명히 보이면 최대 30까지 계속) |
| 돌아오기 | 반대쪽 최대 조향으로 방향을 원래대로 되돌린 뒤 직진(차선이 안 보여도 동작) |
| 넘겨주기 | seg가 새 차선을 보이면 어느 단계든 바로 새 차선 차선추종으로(사람도 그 시점부터 풀었음) |
| 비상 정지 | 차 박스가 화면 아래(y≥440)에서 진행 경로(x 220~420)를 60px 이상 막으면 상태와 관계없이 정지 |

내 차선을 정하는 방법 비교(11-18 기록 507장): best.pt seg가 77%의 장면에서 판단하고, 점선(50%)과 92% 일치, 다를 때는 모두 seg가 맞았습니다
(점선 방식은 주차구역의 주차칸 선을 잘못 잡음). HybridNets의 도로 seg는 초록 매트까지 도로로 칠해 쓸 수 없었습니다.

앞차가 내 차선에 있는지는 가운데 흰 점선으로 확인합니다. 어두운 도로 위에 있고 양옆이 모두 도로인 흰 페인트를
점선으로 보고(가장자리 선은 한쪽이 매트·바닥), 앞차 박스 아래쪽 바로 옆의 점선만 직선으로 맞춰 차가 점선의
왼쪽(lane1)인지 오른쪽(lane2)인지 정합니다. 점선 위에 걸친 차는 내 차선의 차로 봅니다. 점선이 안 보이면 화면
가운데를 가로막은 가까운 차(y≥330)만 내 차선의 차로 봅니다. best.pt의 lane1/lane2 마스크로는 두 차선이
구분되지 않는 경우가 많아(lane2가 도로 전체를 덮음) 이 판단에 쓰지 않습니다.

같은 차가 1초 이상 안 보여야 지나간 것으로 보고, 차선을 옮긴 뒤에도 같은 차가 내 차선에 계속 있으면 정지합니다
(한 프레임 놓쳐도 다시 출발하지 않음). 차선을 놓쳐 정지했거나 빨간불에 서 있을 때는 차가 보여도 출발하지 않습니다.

차선이 안 보이면(가로로 그어진 흰 선, 조명 반사, 앞차에 가림) 바로 서지 않고 직전 1초의 차선 추종
조향으로 150 속도로 `lost_hold_time`(기본 속도 150에서 1.5초)만큼 더 갑니다. 그동안 차선이 다시
보이면 이어서 주행하고, 끝까지 안 보이면 정지합니다.
