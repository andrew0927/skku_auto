# ROS 2 기반 자율주행 차량

2026-11-16에 라이다 추가 직전의 카메라·신호등 주행 버전으로 복구했습니다.
목표점 안정화, 차선 재탐색, 초록불에서의 차선 복구 보정은 유지합니다.
라이다·장애물 회피·자동주차는 기본 비활성화이며, 라이다 없이 실행할 수 있습니다.
모델은 기존 final_best.pt와 동일한 best.pt를 사용합니다.

## 빌드와 실행

ROS 2 Humble 환경에서 작업공간 루트로 이동해 빌드합니다.
이 PC의 루트는 /home/donghyun/ros2_ws/ros2_ws 입니다.

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install
./run_autonomous.sh cam_num:=0 port:=/dev/ttyACM0 target_lane:=lane2
```

lane1 주행 평가는 마지막 인자를 target_lane:=lane1 로 바꿉니다.
카메라, 신호등 판단, 차선 추종, 횡단보도 조향 보정만 기본 활성화됩니다.
라이다 포트는 열지 않고 라이다 데이터가 없어도 주행 준비가 가능합니다.
신선한 카메라/경로/명령 데이터와 빨간불 정지 조건은 그대로 유지합니다.
이 스크립트는 Arduino를 업로드하거나 자동으로 출발시키지 않습니다.

| 조종 입력 | 동작 |
| --- | --- |
| 1 + Enter | 수동주행 |
| 2 + Enter | 차선 자율주행 대기 |
| 3 + Enter | 과거 자동주차 모드. 현재 기본 실행에서는 노드가 꺼져 있어 주행하지 않음 |
| Space | 선택한 자동 모드 시작 / 정지 |
| 실행 중 1 / 2 / 3 | 정지 후 해당 모드의 대기 상태로 전환 |
| w / s, a / d | 수동 속도 ±10, 조향 ±1 |
| x | 정지. 주차 중에는 주차 절차도 초기화 |
| q / Ctrl+C | 정지 후 전체 실행 종료 |

차선 주행과 주차가 별도 명령을 계산하지만, 차량에 전달하는
topic_control_signal의 발행자는 키보드 노드 하나입니다.
주차가 완료되면 DONE 상태에서 정지합니다.

## 차선과 속도

- 정상 속도 255, 다른 차선에서 목표를 추정할 때 200을 유지합니다.
- lane2 미검출 시 lane1에서 lane2를, lane1 미검출 시 lane2에서 lane1을 추정합니다.
  두 차선이 함께 보였을 때 측정한 높이별 간격만 최근 2초 동안 사용합니다.
  측정 이력이 없으면 가짜 목표점을 만들지 않습니다.
- 차선 전환 시 간격 이력은 유지하고, 이전 목표 차선의 중심 이력만 비웁니다.
- 화면 가장자리에서 차선이 잘리면 차선 폭 300픽셀로 중심을 보정합니다.
  목표점이 한 프레임에 55픽셀 이상 움직이면 제한하고, 110픽셀보다 크게 튀면 제외합니다.
  lane_width, max_accepted_step, max_center_step은 차선 추출 노드 파라미터입니다.
- 원근 변환 기준점과 현재의 전방 목표점 기반 조향 계산은 유지합니다.
  예전의 조향 감도·오프셋 숫자를 그대로 복사하지 않습니다.
- 직접/추정 구분과 목표 차선 이름을 원본 영상 시간과 함께 경로 메시지에 전달합니다.
  회피 전환 직후 이전 차선용 경로를 따라가는 일을 막습니다.

두 차선을 모두 놓쳐도 새 영상의 미검출 메시지가 계속 들어오고 실제 자동 주행 중이었다면,
속도 70으로 최대 3초 재탐색합니다. 첫 1초는 마지막 조향을 유지하고,
이후 1초 간격으로 +2 / -2 조향을 사용합니다.
재검출 후에는 속도를 틱당 20씩 정상/추정 속도로 복귀시킵니다.
추정에서 직접 인식으로 바뀌면 기존처럼 0.5초 동안 추정 속도를 유지합니다.
처음부터 차선이 없거나 영상 자체가 끊겼을 때는 이 기능으로 출발하지 않습니다.

## 횡단보도와 신호등

신선한 신호등 검출과 횡단보도 검출이 함께 있을 때만 조향 변화율을 초당 5단계로 제한합니다
(일반 주행 기본값은 초당 10단계). 횡단보도 자체로 정지하거나 속도를 낮추지는 않습니다.
enable_crosswalk_guard와 crosswalk_steering_rate로 조정할 수 있습니다.
신호등이 없는 곳에서 횡단보도만 오검출해도 이 조향 보호는 켜지지 않습니다.

신호등은 영상 상단 45% 안에 있는 traffic_light / trafficlight 검출의 색을 판단합니다.
YOLO가 놓치면 원형 점등부(하얗게 과노출된 중심 포함)의 색 테두리와
인접한 어두운 몸체가 함께 있는지 확인하는 lamp_geometry 보조 검출을 사용합니다.
빨강/주황은 2개, 초록은 3개 연속 새 프레임에서 확인합니다.
주황은 Yellow로 보고하며, 별도의 주황불 정지 규칙은 추가하지 않았습니다.
반복된 영상이나 오래된 영상은 색 확인 횟수와 상태 갱신에 사용하지 않습니다.
이 보조 검출은 제공된 가로형 신호등 사진을 기준으로 검증했으며 현장 전체 조건을 보장하지 않습니다.
traffic_light_debug에서 YOLO 객체 수, 판정 색과 yolo/lamp_geometry 출처를 확인하고,
traffic_light_preview에서 색 판정 박스를 볼 수 있습니다.
traffic_light_presence는 새 영상에서 YOLO 신호등 또는 lamp_geometry 점등부를
찾았는지 나타냅니다. 색이 아직 확정되지 않은 신호등도 포함하며, 오래된 영상이나
중복 영상으로 신호등 존재 상태를 갱신하지 않습니다.

빨간불에서 다음 순서로 정지합니다.

- 이미 정상 자동주행 중이며 신호등, 횡단보도와 경로를 새 영상에서 확인할 수 있을 때만,
  횡단보도까지 PWM 70 이하로 접근합니다. 라이다 회피 사용 시 라이다도 정상이어야 합니다.
  접근을 이미 시작했다면 신호등이 잠깐 가려져도 기존 접근 시간/경로/위치 유효 조건 안에서만 계속합니다.
- 제공된 정지 위치 사진을 기준으로, 횡단보도 바운딩박스의 먼 쪽 경계(상단)가
  화면 위에서 약 67.708%에 닿으면 정지합니다.
  기본 640x480 영상에서는 y=325이며, Camera Image의 빨간 가로선으로 표시합니다.
  사진에서 박스 하단은 본넷 쪽 y=479까지 이어져 위치 기준으로 사용하지 않습니다.
  선은 표시용 복사 영상에만 그려지며 YOLO 입력에는 들어가지 않습니다.
- 횡단보도 미검출/위치 갱신 단절/0.3초보다 오래된 영상, 차선 유실,
  장애물, 최대 접근 시간 3초 초과 시에는 기준선까지 진행하지 않고 정지합니다.
- 빨간불 정지 후 신호등이 None/Unknown으로 바뀌어도 출발하지 않고,
  새 초록불 판단이 들어와야 정지를 해제합니다. 대기/정지 상태에서 빨간불만 보고 출발하지 않습니다.

crosswalk_stop_y_ratio:=0.6770833333333334 로 위치를 조절합니다(0.2~0.95).
crosswalk_stop_edge:=far_edge 가 기본이며, near_edge는 예전의 가까운 쪽 경계 기준입니다.
예전 실행 인자의 crosswalk_stop_y_ratio:=0.5 는 새 기본값을 덮어쓰므로 제거해야 합니다.
값이 작을수록 더 일찍, 클수록 더 가까이 접근해 정지합니다.
crosswalk_approach_speed(70), crosswalk_approach_timeout(3.0),
crosswalk_position_timeout(0.3)도 실행 인자로 조절할 수 있습니다.
red_stop_at_crosswalk:=false 는 위치 접근 없이 즉시 정지하는 동작으로 되돌립니다.
화면상의 위치 기준은 실제 거리나 제동 거리를 보장하지 않으므로 실차 정지 위치를 확인해야 합니다.

현재 조향 보호는 몇 초 전의 차선 경로를 저장해서 통과하는 기능이 아닙니다.
최신 경로의 조향 변화율을 제한하며, 위 빨간불 접근에서도 최신 경로를 사용합니다.
crosswalk_stop_debug 토픽에서 신호등 존재 여부, 횡단보도 조향 보호 활성 여부,
경계 종류와 비율, 정지 기준, 정지 유지 이유를 확인할 수 있습니다.
신호등 판단 메시지가 끊겨도 정지합니다.
obey_traffic_lights:=false 로 평가에서 제외할 수 있습니다.

신호등 색에 따라 차선 검출을 끄는 분기는 없습니다. lane_tracking_debug에는
실제 차선 클래스 미검출(no_lane_detection)과 목표점 부족/급변 제외
(too_few_valid_target_points, rejected)을 구분해 기록합니다.
제공된 초록불 사진은 640x480으로 맞춰도 컬러 추론에서 lane2 점수가 약 0.066으로 떨어졌고,
흑백 입력에서는 lane1 0.944, lane2 0.935, 횡단보도 0.928로 회복되었습니다.
이는 목표점 후처리 이전의 색 분포에 민감한 검출 실패 사례입니다.
촬영 해상도/화각도 다르므로 카메라 노출 설정의 고장이라고 단정하지는 않습니다.

enable_green_grayscale_fallback:=true 가 기본입니다.
현재 목표 차선이 컬러 추론에서 사라졌을 때 흑백 추론을 추가로 시도합니다.
lane2 주행에서 lane1만 보이거나 lane1 주행에서 lane2만 보여도 복구 대상입니다.
target_lane 초기값과 주행 판단 노드의 target_lane 토픽을 함께 따릅니다.
원본 영상의 초록 점등부 또는 최근 1초 이내 신호등 판단 메시지의 Green이 있어야
새 복구를 시작합니다. 초록 관측 문맥은 기본 1초 유지해 순간적인 검출 누락을 보완합니다.
Red/Yellow를 관측하면 이 문맥과 흑백 모드를 즉시 초기화합니다.

복구 성공 후에는 점등부를 한 프레임 놓쳐도 흑백 추론을 유지하며,
기본 0.4초 간격으로만 컬러 추론을 추가 검사합니다. 초록 문맥이 사라지고,
서로 다른 원본 영상의 컬러 검사에서 목표 차선이 연속 3회 검출돼야 컬러로 복귀합니다.
흑백에서 목표 차선을 잃고 컬러에서만 다시 찾은 경우에는 현재 컬러 결과를 사용하고,
3회 확인되면 초록 문맥 중에도 컬러로 복귀할 수 있습니다. 재검사 실패 시 확인 횟수는 초기화합니다.
두 입력에서 모두 실패하면 없는 차선을 만들지 않으며, 재시도 간격을 두어 연산 증가를 제한합니다.
카메라 프레임 처리가 1초보다 오래 끊기면 이전 모드/초록 문맥을 초기화합니다.

컬러 재검사 중에도 복귀 조건이 충족되기 전에는 유효한 흑백 차선을 우선 사용하고,
컬러에서 검출된 신호등과 횡단보도는 유지합니다. 검출 기준 0.5는 낮추지 않습니다.
유지하는 것은 영상 추론 모드이지 과거 차선이나 조향 명령이 아닙니다.
매 영상에서 새로 검출하며, 기존의 오래된 데이터/명령 단절/빨간불 정지 처리는 유지합니다.
카메라 원본 영상과 시간 정보는 바꾸지 않으므로 신호등 색 판단에는 영향이 없습니다.
yolo_inference_debug에서 color / green_grayscale / green_grayscale_cached /
green_grayscale_probe 모드, 목표 차선과 검출 여부, 초록 문맥, 컬러 확인 횟수,
추론 횟수와 처리 시간을 확인할 수 있습니다. 추가 추론에 따른 실차 지연 확인은 필요합니다.
green_context_hold(1.0초), green_color_probe_interval(0.4초), green_color_confirmations(3회)를
실행 인자로 조절할 수 있습니다. 정상/추정 속도, 조향 및 정차 위치 기준은 변경하지 않습니다.
이 보정은 첨부 사진과 단위 테스트에서 확인한 것이며 모든 조명에서의 완주를 보장하지 않습니다.

라이다 미장착 상태에서 신호등 구간을 시험할 때는 다음처럼 실행합니다.

```bash
./run_autonomous.sh cam_num:=0 port:=/dev/ttyACM0 enable_lidar:=false enable_obstacle_avoidance:=false enable_parking:=false
```

카메라 사진 한 장을 모터 통신 없이 같은 모델과 경로 추출기로 확인할 수 있습니다.

```bash
source /opt/ros/humble/setup.bash
source install/local_setup.bash
python3 tools/analyze_frame.py /path/to/camera.png --output /tmp/frame_analysis.json
```

보고서는 원본 크기를 기록하고 실제 주행처럼 640x480으로 맞춘 뒤 분석합니다.
detections/lanes는 원래 컬러 모델의 결과, effective_detections/effective_lanes는
조건부 흑백 복구까지 적용한 결과입니다.

거리 판단은 배열 인덱스가 아니라 LaserScan의 각도 메타데이터를 사용합니다.

목표 차선을 lane2에서 lane1 또는 lane1에서 lane2로 바꿉니다.
다음 회피까지 최소 4.5초를 두고, 같은 물체가 계속 보이면 재전환하지 않고 정지합니다.
물체가 사라진 새 스캔이 들어와야 다음 회피를 허용합니다.
빨간불, 오래된 영상·경로·라이다 데이터는 회피보다 정지가 우선입니다.

enable_lidar:=false 를 쓰면 라이다 포트를 열지 않고 회피도 비활성화됩니다.
라이다 없이 카메라만 시험할 때 사용할 수 있습니다.
주차 모드는 유효한 라이다 데이터가 없으면 출발하지 않습니다.

## 자동주차

기본 실행에서는 비활성화입니다. 아래 과거 코드는 현재 하드웨어 배치와 후방 카메라에
연동된 기능이 아니므로 그대로 후방 주차 시험에 사용하지 마세요.

3번 모드에서 Space를 눌러 시작합니다. 백업의 우측 주차 순서를 사용합니다.

1. 우측 270~280도에서 첫 차량과 빈 공간을 확인합니다.
2. 두 번째 차량을 확인하고 3초 전진한 뒤 0.5초 정지합니다.
3. 우측 최대 조향으로 6.5초 후진하고 3.5초 대기합니다.
4. 우측 조향으로 6.5초 전진한 뒤 15초 직진하고 정지합니다.

기본 주차 PWM은 150입니다. 벽 목표 거리 1.6m, 장애물 기준 3m,
빈 공간 기준 3.5m와 위 시간들은 백업에서 가져온 값이므로 실제 평가장에 맞게 확인해야 합니다.
주차 노드의 파라미터로 조정할 수 있습니다.
차량·갭 확인 횟수는 타이머 횟수가 아니라 새로운 스캔 수로 셉니다.
주차 도중 라이다 데이터가 끊기면 정지하고, 연결 후 x와 Space로 다시 시작합니다.

## 데이터와 명령 단절

- 원본 영상이 1초보다 오래되거나 잘못된 타임스탬프이면 정지합니다.
- 경로 메시지 수신이 0.6초 지연되면, 직전 정상 자동주행에 한해서 추가 0.3초 동안
  마지막 유효 조향과 속도 70 이하로 버팁니다. 이때도 원본 영상은 1초 이내여야 하고,
  신호등 판단과 라이다가 최신이어야 하며 빨간불이나 장애물이 있으면 허용하지 않습니다.
  유예는 새 메시지 없이 연장되지 않으며, 기본 합계 0.9초를 넘으면 정지합니다.
  path_gap_grace:=0.0 으로 유예를 끌 수 있습니다(허용 범위 0~0.5초).
- 라이다 스캔/장애물 판단이 0.6초 동안 갱신되지 않으면 라이다 회피 주행을 정지합니다.
- 자동 명령 또는 키보드 명령이 0.5초 끊기면 차량으로 속도 0을 보냅니다.
- Arduino 펌웨어 자체에는 통신 타임아웃이 없습니다. USB를 물리적으로 뽑으면
  PC가 정지 명령을 전달할 수 없으므로 차량 전원으로 정지해야 합니다.

LaneInfo와 PathPlanningResult에 target_lane 필드가 추가됐으므로
예전 install 폴더를 재사용하지 말고 전체 빌드를 해야 합니다.
Arduino 핀과 보정 끝값은 유지했고 중복된 FORWARD_LEFT_2 선언만 정리했습니다.

```bash
source install/local_setup.bash
```

카메라 사진으로 인식만 실행할 때는 다음과 같이 물리 장치를 비활성화합니다.

```bash
./run_autonomous.sh enable_serial:=false enable_teleop:=false enable_lidar:=false \
  enable_parking:=false data_source:=image show_image:=false
```
